How it works

Screen is a first-pass resume screening tool. A recruiter gets a ranked shortlist with reasons, not just a number.

The problem

One job opening can bring hundreds of resumes. Reading them all by hand is slow, and two recruiters often shortlist differently. Screen does the first pass the same way every time and shows its working.

Two things it does

Rank resumes for a job

Starts from a job description. Upload resumes, get a ranked list. The score rewards evidence: 30% text similarity, 55% skills shown in projects or experience (skills only listed earn 40% credit), 15% depth of described work. Copying the job description is detected and penalised. Each candidate lands in Selected (80 and up), Under review (60 to 80) or Rejected, and the recruiter approves any message sent.

Find a resume's best role

Starts from a resume; no job needed. The system works out the best-fit role (software developer, backend, web, AI/ML, data analyst, DevOps) as percentages, and ranks the person's skills as Primary, Secondary or Mentioned by how often they appear.

How role detection works

Each role is a weighted list of skills. Java, C and C++ weigh heavily for Software Developer; React and JavaScript for Web Developer; PyTorch and NLP for AI/ML. A skill that appears in several projects counts for more than one that sits once in a list. The scores are turned into percentages, and the gap between the top two roles sets the confidence. A narrow gap is shown as Low confidence, because the person has a mixed profile.

Try it in five minutes

  1. Press Load demo data. Five jobs appear, each already scored against 25 sample resumes.
  2. Open Java Developer. Candidates strong in Java, C++ and data structures rank first. Open one to see the score breakdown and best-fit role.
  3. Open Frontend Developer - React. The same resumes now rank in a different order.
  4. Switch to Find a resume's best role and try the demo set. Each resume lands in a role with a confidence level.
  5. Upload a resume of your own (PDF, DOCX or TXT) in either view.

What to keep in mind

  • The demo resumes are invented. They were written to span roles, so the match against their labels is a sanity check, not a benchmark.
  • Matching is by words, not meaning. "Built scalable APIs" is not seen as the same as "REST API development". Embedding-based matching is the planned upgrade.
  • Scanned image PDFs are not readable without OCR.
  • The tool supports a recruiter. It does not decide who gets hired.
